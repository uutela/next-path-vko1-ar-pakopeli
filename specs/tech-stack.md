## Testing

| Package | Why |
|---|---|
| Vitest | `npm test`, fixed by AGENTS.md |
| `@testing-library/react` + jsdom | Component assertions |
| `react-native-web` | Aliased in for component tests, so React Native components render in jsdom |

**Known limitation, stated rather than discovered later.** React Native's own
test tooling is Jest-shaped and does not run under Vitest. Component tests
therefore render through `react-native-web` in jsdom. That verifies the render
tree, the text, the props and the handlers — but jsdom has no layout engine,
so it measures nothing. `ar-panel.md` AC15 was written against this limit
rather than around it: it promises the *declared* style values — `minWidth`
and `minHeight` of at least 48, keypad gap at least 8 — because those are what
a test here can actually read. The rendered size is confirmed once on the
device, and `ar-panel.md` records that as a field check.

The domain layer is plain TypeScript and has none of this friction — it is the
larger part of the test suite and runs directly.

## Deliberately not used

| Not used | Why |
|---|---|
| Google Maps, Mapbox, MapTiler, CARTO | All require an account and an API key; CARTO's own licence restricts free tile service |
| A backend, a database, an auth library | PRD non-goals. Points live in a JSON seed plus device storage |
| Sentry or any analytics SDK | PRD non-goal, and a guardrail: the player's location never leaves the device |
| Redux, Zustand, or any state library | One `useReducer` over `transition` is the whole state layer |
| Unity, 8th Wall | Commercially licensed, which the PRD constraint forbids |

## Install order

The two heavy native packages — MapLibre and Viro — need a custom dev build
and a config plugin; neither works in Expo Go. They are installed when the
code that uses them is written, not before, so that a failed native install
cannot block the harness from working. Everything in Runtime and Testing is
installed now.
